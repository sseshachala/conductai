How Conduct learns

Every run makes the next run smarter.
Every session makes the next agent more like your team.

Two memory systems work together. One knows your codebase. One knows your team. No other automation tool has either.

🧠
Playbook Layer
Contextual Memory

Per-workflow, per-repo. Every playbook reads what worked before it acts, then writes what it learned when it finishes. Captured in recall_context and record_outcome blocks.

Knows which files are fragile
Run 1 explores. Run 10 goes straight to the right file.
Avoids repeating past mistakes
If a fix caused a regression last time, the agent knows. It tries a different approach.
Compounds across every playbook run
A workflow that has run 50 times on your repo is more valuable than a fresh install anywhere else.
How it works
Before every run → reads prior outcomes. After every run → writes what happened. The brain block uses both to make better decisions next time.
👥
CLI Layer
Team Session Memory

Per-developer, across every AI tool. The CLI hook captures sessions passively — what was prompted, accepted, rejected, and how each developer works. Zero extra effort from your team.

Knows how each developer works
Sarah always requires tests. The security lead flags credential exposure. The agent already knows this before it writes a line.
Captured across Copilot, Cursor, Claude, Codex
One CLI hook. All tools. Every session adds to the team's shared context automatically.
The agent behaves like a team member
Not a contractor who just showed up. An engineer who has been with the team for months and knows how things are done here.
How it works
conduct login installs a hook in every AI tool. Each session is captured silently. The team's working patterns accumulate. Playbooks draw on this context automatically.

No other automation tool has either. GitHub Actions has zero memory. Copilot has no team context. Conduct compounds both — silently, continuously, from day one.
