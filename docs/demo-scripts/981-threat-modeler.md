# Demo script — Threat Modeler playbook (Issue #981)

**Duration target:** 3:00–3:30
**Audience:** CISO, security architect, GRC lead, VP Engineering
**Setup required:** A demo repo with an obviously-flawed PR (new endpoint accepts userId param, returns billing data, no ownership check). Conduct workspace with the `threat-modeler` playbook installed. `/secure/findings` open.

---

## Cold open — 0:00 → 0:15

**Voice:** *"Ask an auditor for your threat model. Watch what happens. You get a PDF from last November, three services out of date, two APIs no one remembers. That's not governance. That's paperwork."*

**Screen:** Filing cabinet drawer opening. A single PDF labelled `threat-model-2025.pdf`. Zoom on the date. Fade to a modern dashboard.

---

## Beat 1 — the real problem — 0:15 → 0:45

**Voice:** *"Threat modeling was invented as a workshop. Book two days. Get a security architect. Whiteboard STRIDE. Ship a document. Six months later, the code has moved and the document hasn't. Every regulated org lives with this gap."*

**Screen:** Timeline — threat model dated Nov 2025 on the left. On the right, a git log showing 340 commits and 12 new services since. Red gap between them.

**Voice:** *"Vulnerability scanners don't fix this. A scanner reads code and matches known bad patterns. It cannot tell you your new endpoint returns billing data without checking ownership. That's a reasoning step, not a pattern match."*

---

## Beat 2 — the fix — 0:45 → 1:15

**Voice:** *"Threat modeling is a task the AI in your PR flow can already do. On every merge. Deterministically. Cheap. We shipped it today as one YAML playbook."*

**Screen:** File tree, zoom on `apps/api/playbooks/threat-modeler.yaml`. Scroll through the six blocks — recall, plan, draft_stride, file_findings, comment_pr, record.

---

## Beat 3 — the walkthrough, live — 1:15 → 2:30

**Screen action 1** — open a PR in the demo repo. New endpoint at `apps/api/routes/billing.py` that takes a userId and returns `select * from invoices where user_id = ?`. No ownership check.

**Voice:** *"Real-looking PR. New billing endpoint. Auto-generated by the AI in the developer's IDE. Reviewer will approve it in 30 seconds without noticing the ownership gap."*

**Screen action 2** — the PR immediately gets a Conduct check running. Wait ~30 seconds. Threat Modeler comment appears on the PR:

```
> Threat model auto-drafted by Conduct. 3 threats filed to Guard.

## STRIDE — apps/api/routes/billing.py

| # | Category           | Severity | Threat                                              |
|---|--------------------|----------|-----------------------------------------------------|
| 1 | Info Disclosure    | high     | userId query param returns any user's billing data  |
| 2 | Elevation of Priv  | medium   | endpoint has no role check                          |
| 3 | Repudiation        | low      | no request logging on financial data access         |
```

**Voice:** *"Not generic categories. Specific threats tied to specific lines."*

**Screen action 3** — switch to `/secure/findings`. Three new rows appear with `tool = threat_modeler`. Same UI as scanner findings.

**Voice:** *"Every threat is a finding. Same table as your scanner output. Same MTTR clock. Same compliance rollup."*

**Screen action 4** — click the high-severity finding. Auto-chain to `security-autopilot-fix` playbook. Watch it draft a mitigation PR:

```python
- def get_invoices(user_id: str):
-     return db.query(Invoice).filter_by(user_id=user_id).all()
+ def get_invoices(user_id: str, current_user: User = Depends(get_current_user)):
+     if user_id != current_user.id and not current_user.is_admin:
+         raise HTTPException(403, "Not authorized")
+     return db.query(Invoice).filter_by(user_id=user_id).all()
```

**Voice:** *"Threat detected. Fix drafted. Human approves. Loop closes."*
