The gap nobody talks about

Your team has the engine.
Nobody gave them the vehicle.

🔭

No observation layer

LLMs don't watch your GitHub, CI pipeline, or agent tool calls. They answer when you ask. Automation requires something that listens without being prompted.

🗂️

No persistent context

Each conversation starts cold. Your AI doesn't know the repo layout, the last incident, or who owns this service. Without memory, agents repeat mistakes and ask the same questions.

🔗

No action layer

Generating a fix is not the same as opening a PR, posting to Slack, or running tests. Closing the loop requires real integrations, not copy-paste output from a chat window.

🛡️

No governance

AI agents make calls to external APIs, write files, and push code. Without policy enforcement at the tool level, you find out about the damage after it happens.

The six layers

Everything an agent needs to act, in one platform.

Each layer is a first-class primitive in Conduct — not bolted-on integrations, not configuration files scattered across twelve services.

01
🔭

Observe — catch the signal

Conduct listens to your environment without polling. GitHub webhooks, CI events, and ConductGuard's PreToolUse / PostToolUse hooks fire the moment something happens and hand a structured payload directly to the next block. Agents react in real time, not on a cron.

GitHub webhooks CI events PreToolUse hook PostToolUse hook
02
📚

Build Context — know the codebase

Agent Booster runs a semantic index across your entire codebase and returns only the relevant symbol slices for the task at hand — not a file dump, a precise answer. Combine it with a recall_context memory block to hydrate every run with workspace-scoped facts from prior sessions.

Agent Booster recall_context block semantic search
03
🧠

Reason & Plan — the brain block

Every playbook has a Brain block — a Claude call you configure: model tier, single-turn or agentic mode, and an explicit max_turns turn budget so it never spirals. Use a plan_fix block in single-turn mode to produce a structured plan before handing off to an agentic block that executes it.

Brain block plan_fix block max_turns model-selectable
04
⚡

Act — close the loop

Tool blocks connect reasoning to real outcomes. Open a GitHub PR, post a Slack message, file a Linear issue, run tests in an E2B sandbox, deploy a preview to Vercel. Twelve-plus integrations ship out of the box. The MCP server exposes every block to any MCP-compatible client.

GitHub block Slack block E2B sandbox Modal block Vercel block MCP server
05
💾

Learn & Remember — workspace memory

Memory blocks give agents durable state scoped to your workspace: key-value storage, structured recall, and outcome recording. A record_outcome block at the end of every run writes what happened — so the next agent that touches the same service starts informed, not blank.

memory block record_outcome recall_context key-value store
06
🛡️

Govern & Oversee — ConductGuard

ConductGuard enforces policy at the hook level — before any AI tool call executes. Block, warn, or audit based on workspace policies. Set spend limits per model. Insert approval blocks to require human sign-off before an agent takes a destructive action. Every event is logged to an immutable audit trail.

How it works in practice

All six layers, one GitHub issue.

Here's the autopilot playbook running end-to-end — from a labeled issue to a merged PR, with a human in the loop and guard enforced throughout.

autopilot.yaml
01 — Observe trigger: github_webhook

GitHub issue labeled ai-fix

The GitHub webhook fires the moment the label is applied. Conduct receives a structured payload — issue body, repo, author — and starts the run. No polling. No manual trigger.

02 — Build Context recall_context + agent_booster

AI reads the relevant code

A recall_context block retrieves prior knowledge about this service. Agent Booster runs a semantic search across the codebase and returns only the files and symbols relevant to the issue — not the entire repo.

03 — Reason & Plan plan_fix (mode: single)

Brain block drafts a fix plan

A plan_fix Brain block running in single-turn mode produces a structured JSON plan — files to change, approach, risk notes. It outputs JSON only. No prose, no hallucinated code yet.

04 — Act run_shell + e2b_sandbox

Implements the fix & runs tests

An agentic Brain block executes the plan: edits files, runs the test suite inside an E2B sandbox (isolated, no prod access), and reports pass/fail. The max_turns budget is enforced — the block stops before it can spiral.

05 — Human-in-the-Loop approval_block

Engineer approves before the PR opens

An approval_block posts the diff and test results to Slack and pauses the run. The engineer reviews and clicks Approve or Reject directly in Slack. The playbook resumes only on approval.

06 — Act + Remember github_pr + record_outcome

PR opened & outcome recorded

The GitHub tool block opens a PR with the diff, links it to the original issue, and requests review. A record_outcome memory block writes what was fixed and how — so the next run on this service starts with that context already loaded.

Every step — Govern ConductGuard (always on)

Guard enforced at every tool call

ConductGuard's PreToolUse hook intercepts every action before it executes — sandbox, GitHub, Slack, memory writes. Spend limits prevent runaway model usage. Every event is logged to the immutable audit trail whether the run succeeds or fails.
